# Локализация интерфейса (i18n)

Интерфейс `webui/` переведён на русский через `i18next` + `react-i18next`. Английский остаётся
языком по умолчанию и эталоном: `en.json` — источник ключей, `ru.json` — перевод. Бэкенд
(`backend/`), промпты модели и `src-tauri/` намеренно не менялись — см. [«Намеренно не переведено»](#7-намеренно-не-переведено).

## 1. Как устроен i18n

- **Ресурсы** — обычные JSON (`webui/src/locales/en.json`, `ru.json`), один namespace
  `translation`. Вложенность — по областям интерфейса: `board.card.new`, `harness.toolbar.play`.
- **Инициализация** — `webui/src/i18n/index.ts`, ровно один инстанс на приложение. Экспортируются
  `initI18n()`, `getLanguage()`, `setLanguage(lang)`, сам `i18n` и `SUPPORTED_LANGS = ["en", "ru"]`.
  `initI18n()` идемпотентен и вызывается до первого рендера (см. `src/main.tsx`).
- **Определение языка** при первом запуске: `localStorage["dim0.lang"]` → `navigator.language` →
  `en`. Для неподдерживаемого языка срабатывает `fallbackLng: "en"`, региональные варианты
  схлопываются (`load: "languageOnly"`: `ru-RU` → `ru`).
- **Выбор пользователя** хранится в `localStorage["dim0.lang"]` и переживает перезагрузку.
  Активный язык зеркалится в `<html lang="…">`.
- **Принудительный язык** — переменная окружения `I18N_FORCE_LANG` (или `VITE_I18N_FORCE_LANG`
  для собранного бандла). Если она задана, детектор выключается полностью: ни чтения, ни записи
  `localStorage`, ни `navigator`. Так тесты не зависят от машины разработчика.
- **Интерполяция** — `{{name}}`, `escapeValue: false` (React сам экранирует текст). В JSON нельзя
  вставлять JSX: примеры кода и разметку передаём значением — значения повторно не сканируются.
- **Плюрализация** — CLDR-суффиксы **соседними ключами**, а не вложенным объектом:

  ```json
  "editor.status.words_one": "{{count}} слово",
  "editor.status.words_few": "{{count}} слова",
  "editor.status.words_many": "{{count}} слов",
  "editor.status.words_other": "{{count}} слова"
  ```

  Вызов: `t("editor.status.words", { count })` — наличие `count` включает выбор формы. В `en.json`
  тоже лежат все четыре суффикса (`_one/_few/_many/_other`), чтобы строгая проверка ключей видела
  полный паритет; английские `few/many/other` просто повторяют `_other`. Всего 20 групп.
- **Компоненты** используют `useTranslation()`, модули (например, `features/board/utils/date.ts`,
  `lib/i18n/errors.ts`) — `i18n.t(...)` из `@/i18n`.
- **Ошибки API** — `src/lib/i18n/errors.ts`: типовые HTTP-статусы (400/401/403/404/409/413/429/500/
  502/503/504, а для `/users/signin` ещё 401 → «неверная пара логин/пароль») переводятся ключами
  `errors.*`. Если статус неизвестен, показывается `detail`/`message` сервера **дословно**,
  без обрезки и подмены общим текстом. Неизвестный `detail` остаётся английским — так и задумано.
- **Форматирование** — `Intl`/`toLocaleString` получают `i18n.language` только там, где
  форматирование уже было (`features/board/utils/date.ts`). Ручных `replace(",", ".")` нет.

## 2. Как добавить новую строку

1. Найдите литерал в компоненте: `<span>New Board</span>`.
2. Придумайте ключ по схеме `область.компонент.смысл`, snake_case, и добавьте его в
   `webui/src/locales/en.json` (файл отсортирован по алфавиту). Значение — ровно исходный текст,
   с той же пунктуацией и регистром.
3. Добавьте тот же ключ в `webui/src/locales/ru.json` с переводом. Пустое значение запрещено.
4. В компоненте:

   ```tsx
   const { t } = useTranslation()
   // ...
   <span>{t("board.card.new")}</span>
   ```

   В модуле без React: `import { i18n } from "@/i18n"` и `i18n.t("…")`.
5. Если в тексте есть подстановка — `t("key", { name })` и `{{name}}` в значении. Если это код,
   имя файла или JSX-образец — передавайте **значением**, не вставляйте в JSON:

   ```tsx
   {t("harness.applet.smoke.must_be_array", { example: "`edges`" })}
   ```
6. Если текст зависит от числа — заведите четыре суффикса (`_one/_few/_many/_other`) и вызывайте
   с `{ count }`.
7. Прогоните проверки из [раздела 8](#8-проверка-ключей) и тесты из [раздела 5](#5-тесты).

## 3. Как переключить язык в UI

В боковой панели, рядом с переключателем темы (иконка глобуса), — меню «Язык / Language»:
**English** и **Русский**. Выбор сразу применяется ко всему интерфейсу, сохраняется в
`localStorage["dim0.lang"]` и обновляет `<html lang>`. Перезагрузка не нужна.

## 4. Как обновляться из upstream с минимальными конфликтами

Форк живёт поверх `vcmf/dim0`; наша ветка трогает только `webui/src/**` и добавляет
`webui/src/locales/*.json`, `webui/e2e/i18n-ru.spec.ts`, `scripts/i18n-check.mjs` и этот файл.
Бэкенд, `src-tauri/`, промпты и зависимости без необходимости не меняются.

```bash
git fetch upstream
git switch main
git merge --ff-only upstream/main
git switch feature/i18n-ru
git rebase main            # линейная история; конфликты решаем по правилу ниже
```

Правило разрешения конфликтов: **логику берём из upstream, поверх накатываем `t()`**.

1. В конфликтном `.tsx/.ts` при rebase берём версию upstream (`git checkout --theirs <file>` —
   при rebase «их» сторона это upstream), затем заново оборачиваем новые или изменённые
   пользовательские литералы в `t("…")`.
2. Если upstream удалил или переименовал строку — удалите её ключ из `en.json` **и** `ru.json`
   (в первую очередь из `ru.json`, иначе `i18n:check` покажет лишний ключ).
3. Если upstream добавил новую строку — ей нужен ключ в `en.json` и перевод в `ru.json`.
4. Конфликты в `webui/src/locales/*.json` маловероятны: upstream этих файлов не знает.
   Если случились — оставляем оба набора и сводим вручную.
5. После rebase:

   ```bash
   npm ci
   npm run i18n:check:strict
   npm run check-all
   npx playwright test e2e/local.spec.ts e2e/i18n-ru.spec.ts
   ```

## 5. Тесты

Тесты проверяют английские тексты, поэтому язык в них **принудительно английский**, а не русский:

- **Playwright** — `e2e/setup.ts` пишет `dim0.lang=en` в `storageState` для origin
  `http://localhost:4321`; `playwright.config.ts` подключает это состояние ко всем контекстам.
  Существующие спеки (`local`, `offline`, `parallel-search`, `theme`) не переписывались.
- **Vitest** — `src/test/setup.ts` выставляет `I18N_FORCE_LANG=en`, кладёт `dim0.lang=en` в
  `localStorage` (если он есть) и инициализирует i18next до импорта приложения. Отдельные спеки
  дополнительно вызывают `initI18n()` в `beforeAll`.
- **Русский смоук** — `e2e/i18n-ru.spec.ts` (единственный новый e2e): открывает `/` с `ru`,
  проверяет три русских текста, переход на `/chats` (редирект на русский вход) и отсутствие
  предупреждений `missingKey`, затем через меню языка переключает на `en` и проверяет английские
  тексты и сохранённое значение `dim0.lang`.

Изменённые тестовые файлы (селекторы не переписывались):

- `webui/e2e/i18n-ru.spec.ts` — новый смоук;
- `webui/e2e/setup.ts` — `storageState` с английским языком;
- `webui/playwright.config.ts` — подключение `storageState`;
- `webui/src/test/setup.ts` — принудительный `en` + инициализация;
- `webui/src/lib/i18n/errors.test.ts` — новый тест маппинга ошибок;
- `webui/src/features/connection/connection-indicator.test.tsx`,
  `webui/src/features/connection/offline-overlay.test.tsx` — `initI18n()` в `beforeAll`;
- `webui/src/features/board/harness/node-types/durable-delete.test.ts` — метаданные узлов теперь
  ключи (`titleKey`/`descriptionKey`), проверка обновлена вместе с реализацией.

### 7.3 `@canvas-harness`

Проверены публичные типы `@canvas-harness/core`, `@canvas-harness/react`, `@canvas-harness/sync-broadcast`
(версии из `webui/node_modules`). Пропсов `label`/`locale`/`i18n`/`lang` для пользовательских
подписей нет: `label*`-поля относятся к геометрии подписи ребра (`labelArcLength`,
`labelFollowsTangent`, `labelBackground`), а не к тексту интерфейса. Библиотека не рендерит
собственных пользовательских строк, поэтому передавать в неё нечего; её внутренние тексты, если
появятся, останутся английскими до появления API локализации. Код `harness/canvas/harness-canvas.tsx`
не менялся ради этого.

### 7.4 Дев-экран

`webui/src/features/dev/capture-spike.tsx` исключён из перевода. Маршрут `/dev/capture-spike`
и сам экран подключаются динамическим импортом внутри ветки `import.meta.env.DEV`, которую Vite
схлопывает в `[]` в продакшене, — ни путь, ни код не попадают в `dist/`.

## 8. Проверка ключей

Скрипт `webui/scripts/i18n-check.mjs` не имеет зависимостей и запускается до/без `node_modules`:

- ключ из `en.json` отсутствует в `ru.json` — **ошибка** (exit 1);
- пустое значение в `ru.json` — **ошибка** (exit 1);
- ключ есть только в `ru.json` — предупреждение (exit 0), при `--strict` — ошибка.

```bash
cd webui
npm run i18n:check          # обычная проверка
npm run i18n:check:strict   # + запрет «лишних» ключей
```

Текущий вывод обеих команд:

```text
i18n-check: en=1211 keys, ru=1211 keys
i18n-check: OK
```

Правило: **перед пушем и в CI — `npm run i18n:check`** (в CI достаточно строгого варианта).
ESLint-плагин `i18next` не подключался (не тянем зависимость и не переписываем правила), husky не
добавлялся — проверка остаётся явной командой. `npm run check-all` (`tsc --noEmit` + `eslint .`)
должен быть зелёным вместе с ней.
