# TTS — озвучка ответов агента в Dim0

Модуль добавляет к ответу агента кнопку «Озвучить»: клик — и ответ читается вслух
по-русски голосом Silero. Синтез локальный: ни один API-ключ, ни один внешний
сервис, текст никуда не уходит из вашей машины.

Документ описывает **собранный** модуль: каждая команда и каждый путь в нём
проверяемы по репозиторию.

---

## 1. Как это устроено

```
  Браузер (React SPA)                     Сеть docker compose
 ┌──────────────────────────────┐
 │  Ответ агента в ленте:       │
 │  [Озвучить] [Голос ▾] [☐ авто]│
 └──────────────┬───────────────┘
                │  POST /tts       {"text": "...", "voice": "xenia"}
                │  GET  /tts/voices
                ▼
 ┌──────────────────────────────┐        ┌───────────────────────────────┐
 │  dim0 backend (FastAPI)      │        │  silero-tts (отдельный        │
 │  backend/topix/api/router/   │        │  контейнер)                  │
 │          tts.py              │───────▶│  navatusein/silero-tts-...   │
 │  • модуль выключен → 503     │  form  │  POST /process               │
 │  • латиница → кириллица      │        │  voice=<спикер>&input_text=.. │
 │  • & < > → CDATA             │◀───────│  → audio/wav                 │
 │  • текст → чанки ≤ 250       │  WAV   │  GET /voices → 5 голосов     │
 │  • склейка в один WAV        │        │  GET / → {"status":"work"}    │
 └──────────────────────────────┘        └───────────────────────────────┘
       отдаёт WAV целиком:                  порт 9898, наружу не публикуется
     48 кГц / моно / 16 бит
```

Ключевое правило: **браузер никогда не ходит к сервису синтеза напрямую**. Он знает
только свой API Dim0; всё остальное делает бэкенд.

Эндпоинты бэкенда (роутеры живут в корне, префикса `/api` в проекте нет):

| Запрос | Что делает | Ответ | Ошибки |
|---|---|---|---|
| `POST /tts` | тело `{"text": str, "voice": str \| null}` | бинарный `audio/wav` | 400 — пусто или озвучивать нечего; 413 — длиннее 50 000 символов; 502 — сервис синтеза недоступен или упал; 503 — модуль выключен; 401 — нет авторизации |
| `GET /tts/voices` | список голосов модели | `{"voices": [...]}` | 503 — сервис недоступен или список пуст |

Список голосов бэкенд кэширует ~300 секунд; текст ошибки сервиса наружу не
передаётся — клиент получает нейтральный английский `detail`, а перевод делает
фронтенд.

## 2. Переменные окружения

Все шесть переменных описаны в `.env.sample` (строки 89–101) с комментариями.
Бэкенд получает их двумя каналами: через `environment:` в `build/docker-compose.yml`
и через подключённый в контейнер корневой `.env` (файл `/.env` монтируется
read-only). Поэтому менять их нужно **в корневом `.env` репозитория** и
перезапускать контейнер бэкенда.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TTS_ENABLED` | `false` | Главный выключатель. Модуль выключен → `POST /tts` и `GET /tts/voices` отвечают **503**. Включается значением `true`. |
| `TTS_SERVICE_URL` | `http://silero-tts:9898` | Адрес сервиса синтеза внутри сети compose. Наружу порт не публикуется, менять обычно не нужно. |
| `TTS_VOICE` | `xenia` | Голос по умолчанию — тот, что используется, когда клиент не прислал голос. Один из пяти: `aidar`, `baya`, `kseniya`, `xenia`, `eugene`. |
| `TTS_FORMAT` | `wav` | Формат ответа. Фактически поддерживается только WAV: 48 кГц, моно, 16 бит. |
| `TTS_STREAMING` | `false` | Стриминга в первой версии нет: `StreamingResponse` не используется, клиент получает цельный файл. Флаг оставлен на будущее. |
| `TTS_MODEL_URL` | `https://models.silero.ai/models/tts/ru/v5_6_ru.pt` | Ссылка на файл голосовой модели, который контейнер скачивает при первом старте. Откат на другую версию модели — одна строка в `.env`. |

Переменные `TTS_ENABLED`, `TTS_SERVICE_URL`, `TTS_VOICE`, `TTS_FORMAT` и
`TTS_STREAMING` прокидываются во **всех пяти** сервисах `backend-<stage>`
(`local`, `dev`, `test`, `staging`, `prod`). `TTS_MODEL_URL` читает сам Compose и
передаёт сервису `silero-tts` через переменную `SILERO_SETTINGS`. Сервис
`silero-tts` объявлен один раз и входит во все пять профилей.

## 3. Запуск, включение, смена голоса, выключение

### 3.1 Подготовка окружения

```bash
cp .env.sample .env
```

Дальше откройте `.env` и убедитесь, что есть строка `TTS_ENABLED=true` (по
умолчанию в образце стоит `false` — модуль выключен «из коробки»).

### 3.2 Запуск

Compose-файл лежит в `build/`, поэтому из корня репозитория команда выглядит так:

```bash
docker compose -f build/docker-compose.yml --env-file .env --profile local up -d
```

Профили: `local`, `dev`, `test`, `staging`, `prod`. Подставляется вместо `local`
в примере выше; сервисы бэкенда и фронтенда соответствуют (`backend-local` /
`webui-local`, `backend-dev` / `webui-dev` и так далее), а `silero-tts` поднимается
в любом из пяти.

То же самое через Makefile (короткая форма):

```bash
make up PROFILE=local
```

`make` есть не везде (на Windows без «make» его обычно нет) — тогда используйте
первую команду с `docker compose`.

Убедиться, что сервис жив:

```bash
docker compose -f build/docker-compose.yml --profile local ps silero-tts
```

В колонке состояния должно быть `healthy`. Первый старт длиннее обычного: контейнер
скачивает модель (147 МБ, ~50 с), у healthcheck на это есть `start_period: 60s`.

### 3.3 Как поменять голос

**Через переменную окружения** — голос по умолчанию для всех, у кого в интерфейсе
ничего не выбрано:

```bash
# в корневом .env
TTS_VOICE=kseniya
```

После этого перезапустите контейнер бэкенда:

```bash
docker compose -f build/docker-compose.yml --env-file .env --profile local up -d backend-local
```

**Через интерфейс** — рядом с кнопкой «Озвучить» у ответа агента есть выпадающий
список «Голос» и чекбокс «Озвучивать ответы агента автоматически»:

* список голосов подгружается с сервиса при **первом раскрытии** списка (не при
  открытии чата) и дальше берётся из кэша; имён голосов во фронтенде нет — они
  приходят от модели;
* выбранный голос помнится в браузере под ключом `localStorage` `dim0.tts.voice`,
  флаг автоозвучки — под `dim0.tts.autoSpeak`, поэтому выбор переживает
  перезагрузку страницы;
* пока голос в интерфейсе не выбран, он не отправляется на сервер — и тогда
  работает `TTS_VOICE` из окружения;
* чекбокс автоозвучки по умолчанию выключен: голос, который начинает говорить сам,
  без действия пользователя — хуже, чем отсутствие функции.

В компактном виде (плавающая карточка ответа на доске) остаётся только кнопка-иконка
— без списка голосов и чекбокса; в ленте чата элементы управления показаны полностью.

### 3.4 Как выключить модуль

```bash
# в корневом .env
TTS_ENABLED=false
```

и перезапустить контейнер бэкенда той же командой, что выше. После этого кнопка в
интерфейсе **остаётся видимой** и честно объясняет, что озвучка выключена
(тост «Озвучка отключена»), но больше не отправляет запросов до перезагрузки
страницы. Это осознанное поведение: выключенная функция не должна выглядеть
сломанной.

Останавливать контейнер `silero-tts` для этого не нужно. Если его всё-таки
остановить, кнопка продолжит работать, но будет сообщать «Сервис синтеза речи
недоступен» (код 502) вместо «Озвучка отключена» (503).

Для отладки сервиса можно раскомментировать в `build/docker-compose.yml` строки
`ports:` → `- "9898:9898"` (в файле они оставлены закомментированными рядом с
сервисом `silero-tts`); наружу порт по умолчанию не публикуется.

## 4. Формат звука и как собирается озвучка

**Формат на проводе: WAV, 48 кГц, моно, 16 бит, с RIFF-заголовком — один цельный
файл.** Браузер не перекодирует звук: получает бинарный ответ, делает из него
`Blob` и играет как есть. Base64 в JSON не используется.

**Стриминга в первой версии нет.** Ответ приходит целиком; «сырой PCM» и разбор
заголовков на фронте тоже не используются.

Как из текста получается файл:

1. Текст режется на предложения по `.`, `!`, `?`, `…` и пустой строке. Точки внутри
   известных сокращений (`т.е.`, `и т.д.`, `т.п.`, `т.к.`, `др.`, `см.`, `стр.`,
   `напр.`, `руб.`, `тыс.`, `млн.`, `г.`, `гг.`, `вв.`) концом предложения не
   считаются, поэтому сокращения не рвутся.
2. Предложения короче 50 символов склеиваются со следующим; чанк в итоге не длиннее
   **250 символов**. Единственное исключение — одно предложение длиннее 250
   символов: оно режется по запятой, точке с запятой, двоеточию или тире (это
   осознанный компромисс, отмеченный в коде).
3. **Если чанков не больше двух** — делается один запрос к сервису.
4. **Если чанков три и больше** — по запросу на каждый чанк; PCM-данные кусков
   идут подряд, RIFF-заголовок берётся от первого куска, длина данных
   пересчитывается. Наружу отдаётся один WAV на весь ответ.
5. Если упал хотя бы один чанк — запрос завершается ошибкой **502 целиком**;
   частичного файла пользователь не получит.
6. Каждый уходящий в сервис чанк содержит **целые** CDATA-секции: граница чанка не
   может попасть внутрь экранирующего маркера (иначе сервис получил бы невалидный
   XML).

Ограничения по объёму: текст длиннее 50 000 символов отклоняется с кодом 413,
таймаут вызова сервиса — 15 секунд на каждый чанк.

## 5. Ограничения и особенности

* **Память.** Контейнер `silero-tts` ест 700–900 МБ RSS (около 197 МБ — сам torch,
  около 430 МБ — после загрузки модели). На VPS с 512 МБ оперативной памяти
  модуль не поместится — это ограничение эксплуатации, а не ошибка сборки.
* **Первая загрузка модели.** В образе модели нет: она скачивается при первом
  старте контейнера в volume `silero_models` (147 МБ, ~50 с) и дальше берётся из
  тома. Второй volume `silero_audios` кэширует результаты синтеза.
* **Экранирование делает бэкенд**, по-символьным CDATA-секциями: `&` →
  `<![CDATA[&]]>`, `<` → `<![CDATA[<]]>`, `>` → `<![CDATA[>]]>`. Именованные
  (`&amp;`) и числовые (`&#38;`) сущности использовать нельзя: нормализатор
  сервиса их разрушает (`&amp;` → `&амп;`), и сервис отвечает 400.
* **Латиницу убирает тоже бэкенд** — своей таблицей транслитерации на 52 буквы
  (латиница → кириллица). У модели `ru` расширенного алфавита нет, поэтому
  латинская буква роняет синтез. Порядок обязателен: сначала транслитерация,
  потом экранирование — иначе собственная транслитерация перепишет слово `CDATA`
  внутри нашего же маркера и XML станет невалидным.
* **Числа могут читаться как цифры.** Образ не расширяет числа в слова, так что
  «1000» может прозвучать как «тысяча», а не «одна тысяча».
* **SSML не используется.** Текст уходит чистым, сервис сам оборачивает его в
  `<speak>`.
* **Клонирования голоса нет.** Доступны только пять спикеров модели.
* **Данные наружу не уходят.** Озвучка не попадает в историю чата, запрос идёт
  только на локальный бэкенд и локальный контейнер.

## 6. Ручной чек-лист (шесть пунктов)

Проверяется на машине владельца. Каждый пункт нужно пройти и зафиксировать
результат — «прошло» или «не прошло».

1. **Compose поднимает оба сервиса.**
   *Выполнить:* `docker compose -f build/docker-compose.yml --env-file .env --profile local up -d`
   *Проверить:* `docker compose -f build/docker-compose.yml --profile local ps` — в списке есть `silero-tts` и `backend-local`; у `silero-tts` состояние **healthy** (первый старт дольше: качается модель ~50 с).
   *Результат:* прошло / не прошло.

2. **Кнопка появляется у ответа агента.**
   *Выполнить:* открыть чат и дождаться ответа агента.
   *Проверить:* рядом с кнопкой «Скопировать» у ответа агента есть кнопка «Озвучить»; у собственных сообщений пользователя такой кнопки нет.
   *Результат:* прошло / не прошло.

3. **Клик — слышен русский голос.**
   *Выполнить:* нажать «Озвучить» у ответа агента.
   *Проверить:* в колонках звучит русская речь, произносящая текст этого ответа; кнопка переходит в состояние «играет» (иконка остановки).
   *Результат:* прошло / не прошло.

4. **«Стоп» останавливает звук.**
   *Выполнить:* во время звучания нажать кнопку ещё раз.
   *Проверить:* звук прекращается, кнопка возвращается в состояние «Озвучить».
   *Результат:* прошло / не прошло.

5. **При `TTS_ENABLED=false` — локализованная ошибка.**
   *Выполнить:* поставить `TTS_ENABLED=false` в корневом `.env`, перезапустить `backend-local` командой `docker compose -f build/docker-compose.yml --env-file .env --profile local up -d backend-local`, обновить страницу, нажать «Озвучить».
   *Проверить:* звука нет; вместо него показано сообщение на языке интерфейса («Озвучка отключена»), а не английская строка от сервера; после перезагрузки страницы кнопка снова активна.
   *Результат:* прошло / не прошло.

6. **Смена голоса работает.**
   *Выполнить:* раскрыть список «Голос» у ответа агента, выбрать другой голос, затем нажать «Озвучить».
   *Проверить:* список содержит пять голосов модели; следующий ответ звучит **другим** голосом; после перезагрузки страницы выбранный голос сохранился.
   *Результат:* прошло / не прошло.

## 7. Выбранный образ и модель

| Что | Значение |
|---|---|
| Docker-образ | `navatusein/silero-tts-service:latest` |
| Модель голоса | `v5_6_ru` (`https://models.silero.ai/models/tts/ru/v5_6_ru.pt`) |
| Внутренний порт сервиса | **9898** (наружу не публикуется) |
| Спикеры модели | `aidar`, `baya`, `kseniya`, `xenia`, `eugene` |
| Язык и частота | `LANGUAGE=ru`, `SAMPLE_RATE=48000` |

**Почему выбран именно этот образ.** Решение владельца от 31.10.2026; выбор
подтверждён живым `docker pull` на машине разработки: образ весит **3,73 ГБ**,
индекс `sha256:53f53add…`, мультиархитектурный — **amd64 + arm64** (arm64 нужен,
чтобы модуль работал на MacBook с Apple Silicon). У образа есть опубликованный
контракт, который мы используем: `POST /process` с телом form-urlencoded
(`voice`, `input_text`) на порту 9898 и `GET /voices` списком голосов; GET-образы с
текстом в URL отвергнуты — они упираются в лимиты длины запроса. Модель и список
спикеров задаются через `SILERO_SETTINGS` (обычный JSON в переменной окружения),
поэтому собственный Dockerfile не нужен, а откат версии модели — одна строка
`TTS_MODEL_URL`. Для healthcheck у образа есть `GET /` → `{"status":"work"}`.

| `tts.play` | подпись кнопки в покое | «Озвучить» / «Speak» |

| `tts.unavailable` | сервис синтеза недоступен (502) | «Сервис синтеза речи недоступен» / «The speech service is unavailable» |

`400 → tts.empty`, `413 → tts.too_long`, `502 → tts.unavailable`,

## 11. Конфликты при обновлении форка из upstream

При синхронизации форка `Trikster777/dim0` с upstream эти места будут конфликтовать
в первую очередь — правьте их вручную, сохраняя TTS-часть:

* `.env.sample` — шесть переменных `TTS_*`;
* `build/docker-compose.yml` — сервис `silero-tts`, его volume, healthcheck,
  переменные `TTS_*` и `depends_on` в пяти `backend-<stage>`;
* `backend/topix/api/app.py` — строка подключения роутера
  `include_router(tts.router)` (и импорт `tts` в списке импортов);
* `backend/topix/api/router/tts.py` — роутер TTS;
* `backend/topix/utils/tts.py` — утилиты TTS;
* `webui/src/features/agent/components/chat/actions/speak-answer.tsx` — компонент
  сообщения агента;
* `webui/src/features/agent/components/chat/actions/response-actions.tsx` — строка
  подключения кнопки;
* `webui/src/api.ts` — опция `responseType` и класс `ApiRequestError`;
* `webui/src/lib/i18n/errors.ts` — карта кодов `/tts`;
* `webui/src/components/icons/registry.ts` и `webui/src/components/icons/index.ts` —
  реестр иконок;
* `webui/src/locales/en.json`, `webui/src/locales/ru.json` — блок `tts.*`;
* `TTS.md` — этот документ.

Порядок разрешения: сначала upstream-часть (чтобы не потерять чужие изменения),
затем наши строки поверх — все они аддитивные и не меняют поведение существующего
кода.

## 12. Что осталось за рамками первой версии

* **Стриминг** — `TTS_STREAMING=false`, `StreamingResponse` не используется; звук
  приходит целиком.
* **SSML** — не используется: сервис оборачивает текст в `<speak>` сам, мы шлём
  чистый текст.
* **Клонирование голоса** — не поддерживается, образ его не умеет.
* **Отдельная страница настроек TTS** — настройки живут рядом с ответом агента
  (выпадающий список голосов и чекбокс автоозвучки).
* **Голоса сверх пяти спикеров модели** — список приходит с сервиса, во фронтенде
  он не зашит.

## 13. Известное ограничение платформы (не модуля)

В `webui/playwright.config.ts` сервер для e2e поднимается командой
`APP_PORT=4321 npm run dev`. Это POSIX-префикс присваивания переменной, который
`cmd.exe` на Windows не понимает: Playwright на Windows команду выполнить не может.
На Linux и macOS она работает как есть. На Windows сервер приходится поднимать
вручную в Git Bash с `APP_PORT=4321`.

Это свойство репозитория, а не TTS-модуля: на результаты проверок модуля оно не
влияет.
