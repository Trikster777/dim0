### Критичное ограничение — экранирование XML в бэкенде (проверено вживую 31.10.2026)

Цепочка сервиса (`app/handlers.py:87`): `parse_qs(body)` → поля `voice`, `input_text` →
`normalize(text)` → `text = f'<speak>{text}</speak>'` → `model.save_wav(ssml_text=text, …)` → `sox` → WAV.

1. **`<speak>` добавляет сам сервис.** Наш бэкенд шлёт **чистый текст** и никогда не оборачивает
   его в `<speak>` — двойной обёртки быть не должно.
2. **`normalize()` XML не экранирует**: чистит эмодзи и markdown, переводит числа в слова,
   транслитерирует латиницу — и всё. Сырой `&` или `<` → `<speak>…&…</speak>` → модель бросает
   `Invalid XML format` → сервис отвечает **400** `PlainTextResponse`
   («Silero model failed: Invalid XML format»).
3. **Именованные и числовые сущности тоже не работают** — их разрушает `normalize()`:
   `&amp;` → `&амп;` (транслитерация ASCII-букв `amp`), `&lt;` → `&лт;`,
   `&#38;` → `&#тридцать восемь;` (числа → слова). Живая проверка: `кошка &amp; собака` → **400**.
4. **Рабочая форма — CDATA-секция на каждый символ**: `&` → `<![CDATA[&]]>`,
   `<` → `<![CDATA[<]]>`, `>` → `<![CDATA[>]]>`. Живая проверка: все три варианта → **200 + WAV**.
   `ET.fromstring` склеивает CDATA с текстом (`root.text` = исходные символы), а нормализатор
   сервиса не видит ASCII-буквы внутри маркера (`sub('<[^>]*>','',text)` убирает его целиком),
   поэтому латиница вне маркеров транслитерируется как обычно.
5. **Латиница в тексте роняет модель**: `convert_to_orig` падает с
   `Failed to parse SSML: 'NoneType' object has no attribute 'keys'`, когда в тексте есть буква
   вне русского алфавита (`self.ext_alph` для `ru` = `None`). Обёртка всего текста в CDATA
   сломала бы транслитерацию — поэтому CDATA накрывает только сами символы.

**Значит наш бэкенд перед проксированием обязан экранировать `&`, `<` и `>` через CDATA-секции**
— иначе 502 на ответах агента с амперсандом, HTML или сравнением. Это новая строка требований,
новый пункт брифа и новый тест.

### Независимая проверка живого контейнера (31.10.2026, `docker exec` в работающий контейнер)

Тело `POST /process` собрано `urllib.parse.urlencode`, замеры — по 16-битным сэмплам.

| Что | Результат |
|---|---|
| `Привет мир` | 200, 75 644 Б, 48 кГц, 0.79 с, **peak 23 899** |
| `кошка <![CDATA[&]]> собака` | 200, 94 844 Б, 0.99 с, **peak 24 635** |
| `Отдел Р<![CDATA[&]]>Д отчитался` | 200, 117 644 Б, 1.23 с, **peak 25 959** |
| `воркфлов завершён` | 200, 117 644 Б, 1.23 с, **peak 22 452** |
| `temp.wav` внутри контейнера | тот же peak (21 272…22 452) — `sox` и модель в порядке |

**Ловушка измерения — тело form-urlencoded.** Сервис читает тело через
`parse_qs(body.decode('utf-8'))`, поэтому незаэкранированный `&` внутри значения **молча обрезает
текст**: `input_text=цена 5 & 10` дойдёт как `цена 5 ` (в логе сервиса — `Start text processing:
<speak>цена пять</speak>`). Проба без `urlencode` даёт ложные выводы («сырой `&` → 200», «CDATA →
400»). С `urlencode` живой контейнер совпадает с локальной проверкой **1-в-1**.

Это свойство **формата запроса**, а не сервиса: в бэкенде тело уходит через `httpx` с `data={...}`,
он кодирует сам. Но **тесты обязаны проверять закодированное тело** — иначе они проверяют не тот
контракт (D04).

**Зависимость от версии модели.** Прогон по трём моделям одним и тем же конвейером:

| вход | v5_1_ru | v5_5_ru | v5_6_ru |
|---|---|---|---|
| сырой `&` | 400 | 400 | 400 |
| CDATA `&` / `<` | 200 | 200 | 200 |
| `workflow завершён` (осталась `w`) | **200** | 400 | 400 |
| `формат API и JSON` | 200 | 200 | 200 |

`v5_1_ru` (дефолт образа) латиницу **умеет** — у него задан `ext_alph`. У `v5_5_ru` и `v5_6_ru`
`ext_alph = None`, любая латинская буква в тексте → падение. Мы идём на `v5_6_ru`, поэтому собственная
транслитерация обязательна именно там; при откате на `v5_1_ru` правило останется верным (просто
избыточным).

**Крайний случай — пустой результат, а не ошибка.** Сервис нормализует текст, и некоторые строки
схлопываются в пустоту: `normalize('>')`, `normalize('---')`, `normalize('***')` → `''`. Тогда модель
получает `<speak></speak>` и **возвращает WAV почти без звука, а не ошибку**. Значит бэкенд обязан
отсекать такой текст **до** вызова сервиса — иначе пользователь нажмёт «озвучить» и услышит тишину
без объяснения (D05).

**Провал синтеза кэш не отравляет.** Шесть запросов, давших 400 (`workflow`, `PowerShell`, `Q&A`,
`R&D`, `XML API JSON`, `]]>`), не оставили в `/usr/app/audios` ни одного файла: в кэше лежат только
результаты успешных синтезов.

**Что проверять в коде:** проверять синтез, а не только healthcheck `GET /` — контейнер становится
`healthy` только после загрузки модели, но это не гарантия слышимости.

### Собственная транслитерация латиницы обязательна (живая проверка 31.10.2026)

Сервисная транслитерация (`app/normalizer.py`, `translit_text`) дефектна, и наш CDATA-маркер
дополнительно её ломает:

1. **Неполная таблица.** В ru-таблице нет `q`, `w`, `x` (и `Q`, `W`, `X`) — они остаются
   латиницей. У модели `ru` `ext_alph = None`, любая латинская буква → «Failed to parse SSML:
   'NoneType' object has no attribute 'keys'» → **400**.
2. **Замена по целым словам.** Нормализатор ищет латинские слова в tag-stripped копии и делает
   `text.replace(word, result)` по полному тексту. Когда между латинскими буквами стоит наш
   CDATA-маркер, в копии они склеиваются в один токен (`R&D` → `RD`), а в полном тексте такого
   токена нет → замена молча ничего не делает → латиница остаётся → **400**.

Живые 400 на живом контейнере (без своей транслитерации): `workflow`, `PowerShell`,
`XML`/`API`/`JSON` — «Failed to parse SSML»; `R&D`, `Q&A` — «Invalid XML format».

**Аккумулятор из 16 кейсов на живом контейнере:**

| вариант | успешно |
|---|---|
| сырой текст в сервис | **5 / 16** |
| только CDATA, без своей транслитерации | 5 / 16 |
| полное правило (транслитерация → CDATA) | **16 / 16** |

Во всех шестнадцати успешных случаях — настоящий звук (48 кГц, моно, 16 бит, peak > 17000).

**Значит:** латиницу убирает **бэкенд**, своей таблицей на 52 буквы, **до** экранирования.
Обратный порядок ломает разметку: наша же транслитерация перепишет собственный маркер
(`CDATA` → `ЦДАТА`) → невалидный XML → 400. Пакет `transliterate` в бэкенд не тянем — его
ru-таблица как раз оставляет `q`/`w`/`x` латиницей.

## 3. Адверсариальный проход (по брифу и манифесту)

| | Вопрос | Ответ | Куда идёт |
|---|---|---|---|
| 1 | **Провал.** Сдано, работает, никто не пользуется | `TTS_ENABLED` по умолчанию `false` → на первом запуске кнопка есть, а клик даёт ошибку «модуль выключен». Модуль выглядит сломанным до того, как его включили | **Закрыто владельцем:** кнопка остаётся видимой; первый 503 → один локализованный тост `t('tts.disabled')`, после этого кнопка уходит в неактивное состояние с подсказкой `t('tts.disabled')` до перезагрузки страницы |
| 2 | **Столкновение.** Два требования, которые не могут быть верны вместе | R26 (на выходе один `audio/wav`) против R49 (кроссфейд 10–20 мс **между чанками**) и R43: в одном WAV чанки уже склеены, кроссфейда между ними не сделать. Стриминг требует raw PCM с бэкенда | **Закрыто владельцем:** стриминга в v1 нет — `navatusein` отдаёт готовый WAV, потока не умеет. `TTS_STREAMING=false` по умолчанию, стриминг вне первой версии |
| 3 | **Непроверенное.** Что считают решённым, а оно не решено | «Нажал — слышен русский голос»: здесь нельзя ни стянуть образ, ни запустить контейнер, ни услышать звук. Проверяемо только моками; живой звук проверяется на машине пользователя | ручной чек-лист в отчёте (R60) |
| 4 | **Цена.** Требование, съедающее полсборки ради малой доли ценности | Потоковый режим (R42 + R43 + R49): свой планировщик AudioBuffer, буфер ≥2 чанков, кроссфейд, отмена — при том, что R41 сам же отправляет 1–2 чанка «целиком», то есть стрим почти никогда не включается | **Закрыто владельцем:** вне первой версии. R42/R43/R49 — `deferred`, стриминг уходит в «вне рамок» отчёта |
| 5 | **Условие.** Без чего результат бессмысленен | Модель голоса. У A она запечена → старт всегда; у B качается в рантайме → нужен интернет и кэш. Выбор образа — это и есть условие работоспособности | **Закрыто владельцем:** образ `navatusein/silero-tts-service:latest`, модель `v5_6_ru`, volume на `/usr/app/models` |
| 6 | **Вторая неделя.** Что будет, когда перестанет быть новым | Форк живёт на Sync с upstream: конфликты ожидаемы в 5 файлах (R65). Тег образа — `latest`, но образ активно пересобирается (push 2026-10-22), а версия модели фиксируется нами строкой `TTS_MODEL_URL` в `SILERO_SETTINGS` → поведение модели воспроизводимо, а баг в образе чинится обновлением тега | R65, TTS.md |
| 7 | **Второй актёр.** Кто ещё будет пользоваться | Мини-приложения (iframe-рантайм) и desktop-сборка Tauri живут тем же бэкендом — роутер `/tts` переиспользуем ими; в v1 это вне рамок | «Вне рамок» в отчёте |

Итог: 7 находок. Все 4 вопроса раунда 1 закрыты решениями владельца (31.10.2026), 2 стали
решениями по спецификации, 1 ушла в отчёт. Ни одно требование не снято: адверсариальный
проход не удаляет строки.
