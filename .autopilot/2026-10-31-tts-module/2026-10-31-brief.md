## Контекст
- Мой форк: Trikster777/dim0 (форк от vcmf/dim0, лицензия MIT).
- В форке выполнена русификация (PR #1 смержен, `main` = upstream + 1 squash-коммит):

## Цель
Кнопка «Озвучить» у сообщений агента, озвучивающая ответ на русском. Silero TTS — отдельный
сервис, общающийся с Dim0 по HTTP.

## Принципы (важно)
1. НЕ менять ядро Dim0 сверх необходимого: никаких правок в бизнес-логике агента, чата, холста.
2. TTS-сервис — отдельный контейнер, общается с Dim0 по HTTP.
3. Фронтенд НЕ обращается к TTS-сервису напрямую — только к своему бэкенду Dim0.
   Это убирает CORS и позволяет менять URL сервиса через переменную окружения.
4. Все новые UI-строки — через `t()`, ключи с префиксом `tts.*` в `en.json` и `ru.json`
   (обязательно в обоих, иначе `i18n:check` не пройдёт).
5. Выключатель модуля — переменная окружения `TTS_ENABLED` (по умолчанию `false`).

## Шаг 3. Прокси-эндпоинт на бэкенде
1. Новый роутер `backend/topix/api/router/tts.py`, подключить в `backend/topix/api/app.py`
   одной строкой рядом с остальными `include_router` — существующие роутеры не трогать.
2. Эндпоинт: `POST /tts`
   - Вход: `{ "text": str, "voice": str | null }` (voice по умолчанию из env).
   - Выход: **аудиофайл, `Content-Type: audio/wav`** (бинарный, не base64 — base64
     раздувает поток на треть и портит стриминг).
3. Логика:
   - `TTS_ENABLED` != true → **503** с нейтральным (английским) `detail`;
   - валидация текста: непустой, лимит длины (учесть ограничение GET-образов, см. выше);
     превышение → **413**;
   - проксирование в `TTS_SERVICE_URL` через `httpx.AsyncClient` с таймаутом (~15 с на чанк);
   - ошибка TTS-сервиса → **502** с нейтральным `detail`, без внутренних деталей;
   - стриминг — через `StreamingResponse`, если образ умеет.
4. Никаких API-ключей в коде — только env.
5. [V2] Локализация ошибок — НЕ на бэкенде. По `I18N.md` неизвестный `detail` показывается
   дословно и остаётся английским. Поэтому backend отдаёт нейтральный английский `detail`
   и код ответа (503/413/502), а фронтенд локализует по коду ответа через `t('tts.*')`.
   Иначе в английском интерфейсе потечёт русский текст.

## Шаг 4. Разбиение текста на чанки
1. Утилита `split_text_for_tts(text: str) -> list[str]` (место — по конвенции проекта,
   рядом с другими утилитами; уточни в `backend/topix/utils/`):
   - резать ТОЛЬКО по границам предложений: `.` `!` `?` `…` `\n\n`;
   - НЕ резать по запятым/словам/символам; не ломать сокращения («т.е.», «и т.д.»);
   - короткие предложения (< 50 символов) склеивать со следующим;
   - максимум ~250 символов на чанк; предложение длиннее — резать по запятой/точке с
     запятой/двоеточию/тире (крайний случай) с комментарием в коде, что это компромисс;
   - покрыть pytest: пустой текст, одно длинное предложение, много коротких, текст
     с числами, текст с эмодзи, текст с сокращениями.
2. `/tts`: если чанков 1–2 — синтезировать целиком; если `TTS_STREAMING=true` и образ
   умеет — отдавать чанки по мере синтеза через `StreamingResponse`.
3. [V2] Ловушка формата: Silero отдаёт WAV, и у каждого WAV свой RIFF-заголовок. Если в
   поток идут несколько WAV подряд, фронт получит несколько заголовков и `decodeAudioData`
   упадёт. Варианты: (а) отдавать с бэкенда raw PCM (частота дискретизации — в заголовке
   ответа или в JSON-метаданных), (б) на фронте срезать заголовок и собирать `AudioBuffer`
   вручную. Выбрать один и описать в TTS.md.

- `POST /process`, тело — **form-urlencoded**: `voice=<speaker>&input_text=<текст>` (имена полей
  регистронезависимы, `text` тоже принимается). Ответ — `audio/wav`.
- `GET /voices`, `GET /settings`, `GET /clear_cache`, `GET /` — healthcheck (`{"status":"work"}`).
- Ошибка сервиса приходит не как WAV, а `400` с текстом → наш бэкенд отдаёт фронту 502.
- Сервис сам оборачивает текст в `<speak>…</speak>` — **мы шлём чистый текст, без SSML**.
- Модель скачивается при первом старте контейнера (147 МБ) в `/usr/app/models` — нужен volume.
  Кэш фраз — `/usr/app/audios` (тоже volume).
- Модель в образе не запечена — выбирается через env. В `app/config.py` ссылка лежит в поле
  `silero_settings` (обычный `dict`), а pydantic-settings 2.16 декодирует сложные поля из env как
  JSON. Поэтому свой Dockerfile не нужен:

```yaml
  silero-tts:
    image: navatusein/silero-tts-service:latest
    container_name: silero-tts
    profiles: ["local", "dev", "test", "staging", "prod"]
    environment:
      LANGUAGE: ru
      SAMPLE_RATE: "48000"
      NUMBER_OF_THREADS: "4"
      SILERO_SETTINGS: '{"ru":{"model_link":"${TTS_MODEL_URL:-https://models.silero.ai/models/tts/ru/v5_6_ru.pt}","speakers":["aidar","baya","kseniya","xenia","eugene"]}}'
    volumes:
      - silero_models:/usr/app/models
      - silero_audios:/usr/app/audios
```

Откат на `v5_5_ru`/`v5_1_ru` — одна строка `TTS_MODEL_URL`. Голоса: `aidar, baya, kseniya,
xenia, eugene` (+`random` в самой модели). Дефолт `TTS_VOICE=xenia`.

### 2026-10-31 — критичное ограничение, открытое проверкой вживую

Латиница внутри `<speak>` роняет разбор модели (`Failed to parse SSML`), чисто латинский текст
не синтезируется вовсе. navatusein закрывает это сам: его `normalize()` транслитерирует все
`[a-zA-Z]+` в кириллицу ДО обёртки в `<speak>`. Но XML-спецсимволы он **не экранирует**: сырой `&`
→ «Invalid XML format», сырой `<` → то же (сырой `>` проходит).

**[V3] Уточнение живой проверки:** named-сущности **не работают** — нормализатор транслитерирует
буквы внутри них (`&amp;` → `&амп;`) и разворачивает числа (`&#38;` → `&#тридцать восемь;`),
из-за чего `&amp;` тоже даёт 400 «Invalid XML format». Работает только **CDATA на каждый
опасный символ**: `&` → `<![CDATA[&]]>`, `<` → `<![CDATA[<]]>`, `>` → `<![CDATA[>]]>` → 200 и
корректный WAV. Весь текст в CDATA оборачивать нельзя: латиница спрячется от транслитерации
и уронит модель (в `ru` у модели `ext_alph = None`).

**Значит наш бэкенд перед проксированием обязан экранировать `&` и `<`** (и `>` для симметрии) —
иначе 502 на ответах агента с амперсандом или HTML. Это новая строка требований, новый пункт
брифа и новый тест.

> **Уточнено 31.10.2026** (дополнение «правка контракта текста» ниже): правило экранирования
> **верное и остаётся**, но у него две дыры. (1) Латиницу убирает **наш бэкенд** — у сервисной
> транслитерации два дефекта, из-за которых латиница доходит до модели и роняет синтез.
> (2) Порядок обязателен: **сначала своя транслитерация, потом CDATA**. Причина «весь текст в
> CDATA нельзя» тоже уточнена: не из-за латиницы (её убираем сами), а потому что сервисный
> нормализатор (числа → слова, markdown → чистый текст) перестанет видеть содержимое.
