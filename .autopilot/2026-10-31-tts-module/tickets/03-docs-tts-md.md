## Что должно заработать

В корне репозитория появляется `TTS.md` — документ, по которому человек (не автор кода)
понимает модуль целиком: как он устроен, какие переменные его включают, как его запустить,
как сменить голос, какой звук он выдаёт, где будут конфликты при обновлении форка и чего
модуль не умеет.

Вместе с `TTS.md` появляется фактический материал для финального отчёта владельцу: выбранный
образ и почему он выбран, список новых и изменённых файлов, новые ключи локализации,
результаты всех проверок в трёх категориях, ветка для PR и список того, что осталось за рамками
первой версии. Сам отчёт владельцу собирает оркестратор — таск обязан оставить факты в
`TTS.md` и в описании своего коммита, чтобы отчёт не расходился с кодом.

И отдельным разделом — ручной чек-лист из шести пунктов: что владелец проверяет у себя на
машине, чтобы убедиться, что модуль работает целиком.

> «Отчёт в конце: Новые ключи локализации tts. (en/ru)»

## Критерии приёмки

- [ ] В корне репозитория есть `TTS.md` — и он описывает **собранный** модуль, а не замысел:
      каждая команда и каждый путь в нём существует в коде после тикетов 01 и 02.
- [ ] В `TTS.md` есть диаграмма потока: `frontend → dim0 backend → silero-tts`.
- [ ] Таблица переменных окружения: `TTS_ENABLED`, `TTS_SERVICE_URL`, `TTS_VOICE`, `TTS_FORMAT`,
      `TTS_STREAMING`, `TTS_MODEL_URL` — с дефолтами и смыслом каждой.
- [ ] Инструкция запуска: `docker compose --profile <stage> up -d` для профилей
      `local`, `dev`, `test`, `staging`, `prod`; как поменять голос (через env **и** через
      настройки в интерфейсе); как выключить модуль.
- [ ] Формат звука описан однозначно: WAV, 48 кГц, моно, 16 бит, один цельный файл; правило
      склейки чанков; стриминга в v1 нет.
- [ ] Перечислены места, где ожидаются конфликты при обновлении форка из upstream:
      `.env.sample`, `build/docker-compose.yml`, `backend/topix/api/app.py` (одна строка),
      роутер TTS, утилиты TTS, компонент сообщения агента, `api.ts`, карта ошибок, реестр
      иконок, словари локализации, `TTS.md`.
- [ ] Перечислены ограничения: потребление памяти контейнера и скачивание модели при первом
      старте; экранирование делается на бэкенде (по-символьный CDATA) и латиница убирается
      на бэкенде; числа могут читаться как цифры; SSML не используется; клонирования голоса нет.
- [ ] В `TTS.md` — ручной чек-лист **из шести пунктов**: compose поднимает `silero-tts` и
      `dim0`; кнопка появляется у сообщения агента; клик — слышен русский голос; «стоп»
      останавливает; при `TTS_ENABLED=false` — локализованная ошибка; смена голоса работает.
      Пункты сформулированы так, чтобы их можно было пройти по шагам и зафиксировать
      «прошло / не прошло».
- [ ] В `TTS.md` названы выбранный образ (`navatusein/silero-tts-service:latest`), модель
      (`v5_6_ru`), внутренний порт (9898) и **почему** выбран именно этот образ — с опорой на
      живой `docker pull`: 3,73 ГБ, индекс `sha256:53f53add…`, amd64 + arm64.
- [ ] В `TTS.md` — список новых и изменённых файлов по разделам: backend, frontend, compose,
      docs. Список совпадает с реальным `git diff` двух предыдущих тикетов.
- [ ] В `TTS.md` — список новых ключей локализации `tts.*` (en/ru): `play`, `stop`, `loading`,
      `error`, `disabled`, `too_long`, `unavailable`, `empty`, `voice`, `voicesUnavailable`.
- [ ] В `TTS.md` — результаты проверок, разложенные по **трём** категориям: проверено
      вживью (контракт сервиса, образ, контейнер, compose, экранирование, латиница), проверено
      статически (YAML и все пять `backend-<stage>`, словари, типы, линт, pytest, vitest,
      e2e), не проверено — ждёт машину владельца (звук в колонках, озвучка в UI, сквозной
      `POST /tts` через наш бэкенд). Ни одна проверка не записана как «пройдена», если она
      не проходилась здесь.
- [ ] Назван адрес PR: форк `Trikster777/dim0`, ветка `feature/tts-module` → `main`, **без
      мерджа**. Сам PR открывает оркестратор после приёмки.
- [ ] Назван список того, что осталось за рамками первой версии: стриминг, SSML, клонирование
      голоса, отдельная страница настроек TTS, голоса сверх пяти спикеров модели.
- [ ] `TTS.md` не содержит утверждений, которых нет в коде: каждая команда, каждый путь и
      каждый пример в документе проверяемы.
