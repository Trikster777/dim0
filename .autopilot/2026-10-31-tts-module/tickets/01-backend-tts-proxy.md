## Что должно заработать

Бэкенд Dim0 принимает запрос на озвучку, **сам** готовит текст (латиница → кириллица,
спецсимволы → по-символьный CDATA), режет его на чанки по границам предложений, зовёт контейнер
`silero-tts` и отдаёт **один цельный** WAV. Модуль выключен по умолчанию: пока `TTS_ENABLED`
не `true`, эндпоинт отвечает 503 и к сервису вообще не идёт.

Рядом живёт `GET /tts/voices`: список из пяти голосов приходит с сервиса и нормализуется
в JSON — в коде нет ни одного имени голоса.

В compose появляется **один** сервис `silero-tts` (через YAML-anchor, тем же приёмом, что уже
есть для postgres), с volume под модель и кэш фраз, с healthcheck и **без** опубликованных
портов. Переменные `TTS_*` и `depends_on` появляются во всех пяти `backend-<stage>`.

Живой контейнер на машине владельца уже поднят и проверен — код обязан совпадать с тем, что
проверено вживую, а не с тем, что написано в README образа.

## Критерии приёмки

- [ ] `POST /tts` при `TTS_ENABLED` не `true` → **503** с нейтральным английским `detail`,
      и обращения к TTS-сервису **не было** (проверяется моком: ни одного исходящего запроса).
- [ ] `POST /tts` с пустым текстом → **400**; с текстом, в котором нет ни буквы, ни цифры
      (`>`, `---`, `***`, только эмодзи) → **400**. Оба — **до** обращения к сервису.
- [ ] `POST /tts` с текстом длиннее 50 000 символов → **413**, до обращения к сервису.
- [ ] Сервис отвечает 400 или 5xx → клиент получает **502** с нейтральным английским `detail`;
      текст ошибки сервиса в ответе **не появляется** (ни 4xx, ни 5xx наружу не выходят).
- [ ] Успех → `Content-Type: audio/wav`, **один** цельный файл: RIFF-заголовок, 48 кГц, моно,
      16 бит. Тело ответа **не** завёрнуто в JSON-обёртку (`@with_standard_response` на этом
      эндпоинте не используется).
- [ ] Исходящий запрос к сервису — **form-urlencoded** с `voice` и `input_text`, тело
      закодировано: `&` внутри текста доезжает до сервиса **целиком**, а не обрезается.
      Тест проверяет именно закодированное тело.
- [ ] Подготовка текста идёт в порядке «транслитерация → экранирование». Ассертов **два**:
      (а) `transliterate_latin("Отдел R&D отчитался")` → `Отдел Р&Д отчитался`, латинских букв
      в результате нет; (б) из `prepare_tts_text(...)` CDATA-маркеры сняты регуляркой
      `re.sub(r"<!\[CDATA\[.*?\]\]>", "", text)` — в остатке латинских букв нет.
      Наивная проверка «в `prepare_tts_text` нет латинских букв» не используется: слово `CDATA`
      внутри наших же маркеров латиницей **есть**.
- [ ] `prepare_tts_text` — единственная точка входа: вызывающий код (роутер) зовёт только её;
      `transliterate_latin` — внутренний шаг. Шаги не переставлены местами (иначе наша же
      транслитерация перепишет `CDATA` → `ЦДАТА`).
- [ ] Текст с `&`, `<`, `>` уходит в сервис с по-символьным CDATA. Named- и numeric-сущности
      (`&amp;`, `&#38;`) **не используются** — нормализатор сервиса их разрушает.
- [ ] Латиница не доезжает до сервиса: `workflow`, `PowerShell`, `XML`, `API`, `JSON`, `R&D`,
      `Q&A`, `Qwen` после подготовки — кириллица. Пакет `transliterate` в бэкенд **не** добавлен,
      сервисной транслитерации не используем (у неё нет `q`/`w`/`x`, и она бьёт по целым словам).
- [ ] `split_text_for_tts`: границы только `.` `!` `?` `…` `\n\n`; «т.е.» и «и т.д.» целы;
      предложение короче 50 символов склеено со следующим; длина каждого чанка ≤ 250;
      предложение длиннее 250 режется по запятой/точке с запятой/двоеточию/тире (в коде
      помечено, что это компромисс).
- [ ] Один или два чанка → **один** запрос к сервису. Три и больше → каждый чанк
      синтезируется отдельно, PCM кусков склеивается в один WAV (RIFF-заголовок — от первого,
      длина данных пересчитывается). Сбой любого чанка → **502** целиком, **без** частичного файла.
- [ ] `voice` из тела доезжает до сервиса; при отсутствии `voice` берётся `TTS_VOICE` из env.
- [ ] `GET /tts/voices` → JSON `{"voices": [...]}`, собранный из многострочного plain-text
      ответа сервиса (по голосу в строке, не JSON). Сервис опрашивается не чаще раза в ~300 с
      (кэш). Сервис недоступен или список пуст → **503**.
- [ ] Оба эндпоинта закрыты авторизацией, как остальные: без токена → **401**.
- [ ] В compose сервис `silero-tts` описан **один раз** через YAML-anchor, с
      `profiles: [local, dev, test, staging, prod]`, с volume под модель и под кэш фраз,
      с healthcheck на `GET /`, и **без** опубликованных портов (рядом — закомментированная
      строка для отладки). В `depends_on` — map-форма с `condition: service_started`.
- [ ] `TTS_*` и `depends_on` есть во **всех пяти** `backend-<stage>`, а не только в `backend-local`.
- [ ] В `.env.sample` есть `TTS_ENABLED` (дефолт `false`), `TTS_SERVICE_URL`
      (`http://silero-tts:9898`), `TTS_VOICE` (дефолт `xenia`), `TTS_FORMAT` (дефолт `wav`),
      `TTS_STREAMING` (дефолт `false`), `TTS_MODEL_URL` — с комментариями, плоским
      `KEY=value`, в конце файла.
- [ ] Модель и образ — как проверено вживью: образ `navatusein/silero-tts-service:latest`,
      внутренний порт **9898**, модель `v5_6_ru`, пять спикеров (`aidar`, `baya`, `kseniya`,
      `xenia`, `eugene`), `SILERO_SETTINGS` задаёт язык, ссылку на модель и список спикеров.
- [ ] Новых зависимостей нет: ни в `backend/pyproject.toml`, ни в `webui/package.json`.
      Ни одного API-ключа в коде — всё через env.
- [ ] Тесты зелёные: отдельный набор для `split_text_for_tts`
      (`backend/test/unit/utils/test_tts_utils.py`) и для `/tts`
      (`backend/test/unit/api/router/test_tts_router.py`) — с моком сервиса через
      `httpx.MockTransport`; покрыты 503 / 400 (пустой и «схлопывающийся» текст) / 413 / 502 /
      200 + WAV / CDATA-экранирование / передача голоса / список голосов.
- [ ] Полная проверка зелёная: `( cd webui && npm run check-all && npm run test:run ) && ( cd backend && uv run ruff check topix test/unit && uv run pytest test/unit )`
      — это ровно `make check`, просто без `make` (его на машине нет).
- [ ] В ядре агента, чата и холста **ни одной правки**; подключение роутера — одна строка
      `include_router` рядом с остальными; существующие роутеры и их формат ответов не тронуты.
