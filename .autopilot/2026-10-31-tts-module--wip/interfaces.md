# Границы, швы и правила проекта

Файл, который читает первый каждый исполнитель и ревьюер. Здесь решено **кто что владеет**,
**что чем делится** и **где проходят швы для тестов** — чтобы параллельные задачи не построили
вторую реализацию одного и того же.

Источники: `spec.md` (контракт), `notes.md` (как устроен репозиторий на самом деле),
`audit.md` (контракт сервиса), `carried.md` (договорённости прошлого прогона).

## Границы, решённые в спецификации

### 1. `backend/topix/api/router/tts.py` — HTTP-поверхность модуля

**Владеет:** весь TTS-HTTP: включён ли модуль, валидация текста, выбор голоса, экранирование,
чанкование, проксирование к сервису, склейка WAV, кэш списка голосов, коды ответов.

**Выставляет наружу** (ровно два пути, оба под `Depends(get_current_user_uid)`):

| Путь | Тело | Ответ | Ошибки |
|---|---|---|---|
| `POST /tts` | `{"text": str, "voice": str \| null}` | бинарный `audio/wav` | 503 (модуль выключен), 413 (пусто / > 50 000), 502 (сервис) |
| `GET /tts/voices` | — | JSON `{"voices": ["…"]}` | 503 (сервис недоступен или список пуст) |

**Прячет:** контракт сервиса (`POST /process`, form-urlencoded), правила экранирования,
правило чанкования, устройство WAV, кэш, таймауты. Наружу — только код ответа и нейтральный
английский `detail`. Текст ошибки сервиса наружу **не выходит** (и 4xx, и 5xx → 502).

**Не делает:** не переводит строки (правило `I18N.md` §7.1), не оборачивает ответ в
`@with_standard_response`, не ветвится по `TTS_FORMAT`, не стримит.

### 2. `backend/topix/utils/tts.py` — чистые функции текста

**Владеет:** правила работы с текстом. Ничего не знает про HTTP — и потому тестируется без мока.

**Выставляет:**

```python
def split_text_for_tts(text: str) -> list[str]: ...        # чанки ≤ 250 символов
def prepare_tts_text(text: str) -> str: ...                # ЕДИНСТВЕННАЯ точка входа: шаг 1 → шаг 2
def transliterate_latin(text: str) -> str: ...             # внутренний шаг 1 (в тестах — чистая функция)
def has_speakable_content(text: str) -> bool: ...         # есть ли буква или цифра
def assemble_wav(chunks: list[bytes]) -> bytes: ...         # один WAV из PCM-кусков
```

**Прячет:** границы предложений (`.` `!` `?` `…` `\n\n`), склейку коротких предложений,
крайний случай длинного предложения, формат RIFF-заголовка.

`has_speakable_content` — признак «нечего озвучивать»: в тексте нет ни одной буквы и ни одной
цифры. Сервис на таком тексте (`>`, `---`, `***`, только эмодзи) вернул бы WAV почти без звука,
а не ошибку — поэтому роутер отсекает его **до** вызова сервиса (400).

**Прячет (важно) — `prepare_tts_text` это ЕДИНСТВЕННАЯ точка входа, порядок внутри неё нарушать нельзя:**

`prepare_tts_text(text)` = шаг 1 → шаг 2, оба **внутри одной функции**:

1. **шаг 1 — `transliterate_latin`**: **своя** таблица на 52 буквы, латиница → кириллица
   (`q`→`к`, `w`→`в`, `x`→`кс`, `y`→`й`). После шага в тексте не остаётся ни одной латинской
   буквы: у модели `ru` `ext_alph = None`, любая латинница роняет синтез.
2. **шаг 2 — экранирование CDATA**: **только** на `&`, `<`, `>`: `<![CDATA[&]]>`, `<![CDATA[<]]>`,
   `<![CDATA[>]]>`.

`transliterate_latin` — **внутренний** шаг, а не второй вход: вызывающий код зовёт только
`prepare_tts_text`; наружу `transliterate_latin` торчит только ради прямого теста чистой функции.
Если шаги переставить местами, наша же транслитерация перепишет собственный маркер
(`CDATA` → `ЦДАТА`) → невалидный XML → 400.

**Важно про ассерт «нет латинских букв»:** в финальной строке `prepare_tts_text` латиница
**есть** — это слово `CDATA` внутри наших же маркеров (`<![CDATA[&]]>`). Поэтому ассертов
**два**: (а) на шаге 1 — `transliterate_latin("Отдел R&D отчитался")` → `Отдел Р&Д отчитался`,
латинских букв нет; (б) на финальной строке — **снять маркеры регуляркой**
`re.sub(r"<!\[\[CDATA\[.*?\]\]>", "", text)` и проверить остаток. Наивная проверка
«в `prepare_tts_text` нет латинских букв» всегда красная.

Весь текст в CDATA оборачивать нельзя — сервисный нормализатор (числа → слова, markdown → чистый
текст) перестанет видеть содержимое.

Named- и numeric-сущности использовать нельзя: нормализатор сервиса их разрушает
(`&amp;` → `&амп;`, `&#38;` → `&#тридцать восемь;`).

Сервисной транслитерации доверять нельзя: в её ru-таблице нет `q`, `w`, `x`, а замена идёт по
целым словам — наш CDATA-маркер рвёт слово (`R&D` → в копии `RD`, в оригинале `R`…`D`), и замена
молча не срабатывает. Пакет `transliterate` в бэкенд не тянем: его ru-таблица оставляет
`q`/`w`/`x` латиницей.

### 3. `webui/src/features/agent/components/chat/actions/speak-answer.tsx` — кнопка

**Владеет:** состояние кнопки, воспроизведение, отмена, список голосов, чекбокс автоозвучки,
реакция на 503 (тост + неактивное состояние до перезагрузки).

**Выставляет:** компонент с единственным пропом `answer: string` — тот же текст, что копирует
`CopyAnswer`. Всё остальное — внутри.

**Прячет:** `AbortController`, `URL.createObjectURL` / `revokeObjectURL`, чтение `localStorage`
(`dim0.tts.voice`, `dim0.tts.autoSpeak` — по образцу `dim0.lang` из `webui/src/i18n/index.ts`),
модульный кэш списка голосов: запрос `GET /tts/voices` уходит **при первом раскрытии** списка,
а не при монтировании сообщения; дальше — из кэша, без повторных запросов.

**Зависит от:** `api.ts` (HTTP) и `errors.ts` (код → ключ локализации). Сам HTTP не делает.

### 4. `webui/src/api.ts` — HTTP-общий слой

**Владеет:** запросами к бэкенду Dim0, авторизацией, обработкой ошибок.

**Выставляет (аддитивно, существующее не ломаем):**

- расширение `apiFetch` опцией бинарного ответа (`responseType: "blob"`) — отдельный вызов
  с `Blob`, потому что существующий `apiFetch` для не-JSON делает `res.text()` и портит звук;
- класс ошибки с полями `status` и `endpoint` (прецедент — `SendMessageError`), иначе фронт
  не сможет отличить 503 от 502 от 413 и локализует ошибку.

**Прячет:** URL API, токен авторизации.

### 5. `webui/src/lib/i18n/errors.ts` — код ответа → ключ

**Владеет:** отображением ошибки по коду ответа.

**Выставляет:** одну новую запись — `ENDPOINT_STATUS_KEYS["/tts"]` =
`{400: "tts.empty", 413: "tts.too_long", 502: "tts.unavailable", 503: "tts.disabled"}`.

**Прячет:** ничего. Существующие записи не трогаем.

### 6. `webui/src/components/icons/registry.ts` + `index.ts` — иконка

**Владеет:** экспортом иконок приложения.

**Выставляет:** `SpeakerHighIcon`. Сейчас он есть **только** в `picker-set.ts` и наружу не
выставляется: `registry.ts` — единственное место, где глиф становится компонентом
(`export const SpeakerHighIcon = createPhosphorIcon(SpeakerHighGlyphIcon)`, глиф алиасится
при импорте), `index.ts` — реэкспорт из `registry.ts`.

### 7. `webui/src/locales/{en,ru}.json` — словари

**Владеет:** пользовательскими строками.

**Выставляет:** десять ключей `tts.*` в **обоих** словарях: `play`, `stop`, `loading`, `error`,
`disabled` (из брифа) + `too_long` (413), `unavailable` (502), `voice` (подпись выпадающего
списка), `voicesUnavailable` (список голосов не пришёл), `empty` (400 — озвучивать нечего).

**Прячет:** имена голосов — в словарях их нет, они приходят с сервиса.

### 8. `build/docker-compose.yml` — контейнер `silero-tts`

**Владеет:** описанием сервиса синтеза и подключением backend'а к нему.

**Выставляет:** сервис `silero-tts` (один раз, `profiles: [local, dev, test, staging, prod]`,
`container_name: silero-tts`), переменные `TTS_*` и `depends_on` — **во всех пяти**
`backend-<stage>`.

**Прячет:** внутренний порт 9898 наружу не публикуется; наружу — только имя сервиса в сети.

### 9. `TTS.md` — документация модуля

**Владеет:** описанием для человека: архитектура, переменные, запуск, голос, формат звука,
конфликты с upstream, ограничения.

## Швы для тестов

Чем меньше швов, тем лучше — берём существующие.

| Шов | Что позволяет проверять без сети |
|---|---|
| `httpx.MockTransport` | весь исходящий HTTP бэкенда: 400 / 503 / 413 / 502 / 200 / экранирование / передача голоса (прецедент — `backend/test/unit/agents/test_parallel_search.py`). **Проверять закодированное тело**: тело уходит `httpx` с `data={...}` (form-urlencoded), и незаэкранированный `&` внутри значения молча обрезает текст — тест на сыром теле проверял бы не тот контракт |
| `os.getenv` | `TTS_ENABLED`, `TTS_SERVICE_URL`, `TTS_VOICE` — через `monkeypatch`/патч env |
| чистые функции `utils/tts.py` | чанкование, транслитерация латиницы, экранирование, склейка WAV — без моков вообще. Ассерты латиницы — **два**: (а) `transliterate_latin("Отдел R&D отчитался")` → `Отдел Р&Д отчитался`, латинских букв нет; (б) из `prepare_tts_text(...)` снять CDATA-маркеры `re.sub(r"<!\[\[CDATA\[.*?\]\]>", "", text)` — в остатке латинских букв нет (в финальной строке латиница есть — это `CDATA` внутри маркера, и наивная проверка всегда красная) |
| `MockTransport` + многострочное тело | `GET /tts/voices`: plain-text ответ сервиса → JSON-массив; недоступный сервис → 503 |
| фронт: `apiFetch` с `responseType: "blob"` | `Blob` → `URL.createObjectURL`; тест на то, что `audio/wav` не испорчен `res.text()` |

**Не тестируем через:** настоящий контейнер в CI ( heavyweight, и его нет в репозитории) —
живой прогон идёт смоук-скриптом у владельца.

## Правила проекта (из `notes.md`, `I18N.md`, `carried.md`)

**Бэкенд**

1. Роутеры подключаются в **корень** — префикса `/api` в проекте нет. `APIRouter(prefix="/tts")`
   даёт ровно `POST /tts` и `GET /tts/voices`.
2. Переменные окружения — обычный `os.getenv(...)` (без pydantic-settings).
3. `httpx.AsyncClient(timeout=…)`; `httpx` уже в зависимостях.
4. Тесты — `backend/test/unit/`, `backend/pytest.ini` (`asyncio_mode = auto`).
5. Существующие роутеры не переписываем — только добавляем (`include_router` одной строкой
   рядом с остальными).
6. `@with_standard_response` на TTS-эндпоинт **не вешаем**: он оборачивает тело в JSON-обёртку
   и перехватывает `HTTPException` — бинарный WAV так не пройдёт.

**Фронтенд**

7. Все новые строки — через `t()`; ключи `tts.*` обязательно в **обоих** словарях
   (`npm run i18n:check` следит за паритетом; сейчас по 1211 ключей в каждом).
8. `apiFetch` — единственная точка HTTP к своему бэкенду; наружу (в TTS-сервис) фронт не ходит.
9. В `.tsx` меняются только строковые литералы на `t()` — разметка, пропсы и логика не трогаются.
10. Новые зависимости не тянем (`webui/package.json` не меняется).
11. Иконки — только через `registry.ts` → `index.ts`.

**Compose и окружение**

12. Файл — `build/docker-compose.yml` (не корень); профилей пять: `local`, `dev`, `test`,
    `staging`, `prod`.
13. `depends_on` в файле везде **списком**; для `silero-tts` — **map-форма** с
    `condition: service_started` (бриф требует условие, в списке его не выразить) — это
    единственное отступление от конвенции, и оно осознанное.
14. `.env.sample` — **не** `.env.example` (такого файла в проекте нет); 87 плоских
    `KEY=value` строк, TTS-переменные добавляются туда с комментариями.
15. Backend получает env двумя каналами: `environment:` **и** монтирование
    `../${ENVFILE:-.env}:/.env:ro` — TTS-переменные можно класть в корневой `.env`.

**Проверки**

16. Единая команда — `make check` (= `test-ci` = `lint-ui` + `test-ui` + `lint-backend` +
    `test-backend`). Отдельно: `npm run check-all`, `npm run i18n:check`,
    `npx vitest run` (базовая линия 169 файлов / 1722 теста — не должна уменьшаться),
    `npx playwright test e2e/i18n-ru.spec.ts`.

**Договорённости прошлого прогона — не пересматривать** (из `carried.md`)

17. Бэкенд Python и системные промпты LLM не переводим: правка = конфликты при Sync fork.
18. Переключатель языка — в футере сайдбара рядом с темой, без новых панелей; ключ
    `localStorage.dim0.lang`.
19. ESLint-плагин i18next не включаем, husky не добавляем; полнота — через `npm run i18n:check`.
20. `@canvas-harness/*` и `src-tauri` остаются английскими.
21. Русские формы CLDR: `_one/_few/_many/_other`; `en.json` тоже содержит все четыре ради
    строгого паритета.
22. Глоссарий и правила локализации — в `I18N.md`, раздел 6.

**Конфликты с upstream при Sync форка** (R65)

`.env.sample`, `build/docker-compose.yml`, `backend/topix/api/app.py` (одна строка
`include_router`), `backend/topix/api/router/tts.py`, `backend/topix/utils/tts.py`,
`webui/src/features/agent/components/chat/actions/speak-answer.tsx`,
`webui/src/features/agent/components/chat/actions/response-actions.tsx`,
`webui/src/api.ts`, `webui/src/lib/i18n/errors.ts`, `webui/src/components/icons/registry.ts`,
`webui/src/components/icons/index.ts`, `webui/src/locales/{en,ru}.json`, `TTS.md`.

## Как собрать и проверить

**Стек и версии.** Бэкенд: Python **>= 3.13** (в репозитории есть `backend/.venv` на 3.13.15),
FastAPI **0.128.0**, `httpx >= 0.28.1` (уже в зависимостях), pydantic v2, пакетный менеджер —
**uv**. Фронтенд: Node **^20 || ^22**, React **19.1**, TypeScript **~5.8.3**, vitest **4.1**,
`@playwright/test` **1.61**, i18next **26.5**, `sonner` **2.0** (тосты).

**Установка.** Бэкенд — `cd backend && uv sync` (или `uv run …` без установки: uv сам
доставит окружение). Фронтенд — `cd webui && npm ci`. Новых зависимостей не добавляем:
ни в `backend/pyproject.toml`, ни в `webui/package.json` (R69).

**Одна команда проверки (типы + линт + тесты вместе)** — из корня репозитория:

```bash
make check        # = lint-ui + test-ui + lint-backend + test-backend
```

Точечно:

```bash
cd backend && uv run pytest test/unit            # весь unit-набор бэкенда
cd webui  && npm run check-all                   # tsc + eslint
cd webui  && npm run i18n:check                  # паритет en/ru
cd webui  && npx vitest run                     # весь юнит-набор фронта
cd webui  && npx playwright test e2e/i18n-ru.spec.ts
```

**Один тестовый файл:**

```bash
cd backend && uv run pytest test/unit/utils/test_tts_utils.py -v
cd backend && uv run pytest test/unit/api/router/test_tts_router.py -v
cd webui  && npx vitest run src/features/agent/components/chat/actions/__tests__/speak-answer.test.tsx
```

**Чего нельзя трогать.** Ядро агента, чата и холста (R03); существующие роутеры и компоненты —
только добавлять рядом, ничего не переписывая (R67); `webui/package.json` и
`backend/pyproject.toml` — без изменений; `backend/topix/api/app.py` — **одна** строка
`include_router`; `webui/src/api.ts` и `webui/src/lib/i18n/errors.ts` — только аддитивно;
`build/docker-compose.yml` — только сервис `silero-tts` и переменные `TTS_*` в пяти
`backend-<stage>`; словари — только новый блок `tts.*`; `src-tauri` и `@canvas-harness/*`
остаются английскими.

**Чего нельзя делать в этом прогоне.** Трогать `dim0` upstream-логику, менять формат ответа
существующих эндпоинтов, добавлять зависимости, публиковать порт TTS-сервиса наружу,
переводить backend-Python, включать ESLint-плагин i18next и husky.
