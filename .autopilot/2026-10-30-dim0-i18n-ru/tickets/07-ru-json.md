## Что должно заработать

`ru.json` покрывает весь `en.json` живым русским текстом: кнопки — короткие глаголы, сообщения
вежливые, ошибки понятные, sentence case. Термины строго по глоссарию (одна строка — один перевод),
счётчики — CLDR-формы `_one/_few/_many/_other` (en — `_one/_other`). В приложении при `ru` не остаётся
английских UI-строк, кроме задокументированных; консоль чиста от `missingKey`. Появляется единственный
e2e-смоук `e2e/i18n-ru.spec.ts`.

## Из брифа, дословно

> «`ru.json` — тот же набор ключей, но значения на русском (переведи все ключи качественно, с учётом UX-контекста: кнопки — короткие глаголы, сообщения — вежливые, ошибки — понятные).»
> «i18next для русского использует CLDR-категории: one / few / many / other ... Проверь на 1, 2, 5, 21, 1.5 ... В en.json достаточно _one и _other»
> «Добавь ОДИН e2e-смоук на русский: e2e/i18n-ru.spec.ts ... выставить dim0.lang=ru, открыть главную, проверить 2–3 видимых русских текста, переключить обратно на en»
> «Переписывать существующие 26 селекторов на data-testid — НЕ делаем в этой задаче.»

## Критерии приёмки

- [ ] `npm run i18n:check` зелёный; `npm run i18n:check:strict` зелёный; пустых значений нет
- [ ] Все счётчики имеют четыре формы в `ru`; проверка на `1 / 2 / 5 / 21 / 1.5` даёт «1 доска / 2 доски / 5 досок / 21 доска / 1,5 доски» (лог в отчёт)
- [ ] `Intl`/`toLocaleString` используют `ru-RU` при `ru` и `en-US` при `en` только там, где форматирование уже было; ручных `replace(',', '.')` нет
- [ ] `npx playwright test e2e/i18n-ru.spec.ts` зелёный: `ru` → 2–3 русских текста → переключение на `en` → английский текст
- [ ] В консоли на `/` и `/chats` при `ru` нет `missingKey`
- [ ] Существующие e2e не изменены, 26 селекторов не переписаны
