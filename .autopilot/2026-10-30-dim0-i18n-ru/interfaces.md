# Границы, решённые в спецификации

Читается каждым исполнителем и ревьюером до кода. Меняется только через спецификацию.

## Стек, запуск, проверки

- Node `^20 || ^22` в `engines` (на машине 24 — `npm install` предупреждает, но работает). Пакетный менеджер — только `npm`.
- Установка: `cd webui && npm install` (первый раз; дальше `npm ci` не обязателен).
- Файл `../.env` (корень репозитория) **обязателен** для `npm run dev`/`npm run build`: `dotenv-cli` падает без него. Копировать из `.env.sample`, секреты не нужны, `.env` не коммитится.
- Dev-сервер: `cd webui && npm run dev` (порт `APP_PORT` из `.env`, по умолчанию 5175). E2E поднимает свой на 4321.
- **Единая проверка после правки:** `cd webui && npm run check-all && npm run i18n:check` (пока `i18n:check` не создан — только `check-all`).
- Один тест-файл: `cd webui && npx vitest run <путь.test.ts>`; один e2e: `cd webui && npx playwright test e2e/<файл>.spec.ts --reporter=line`.
- Сборка: `cd webui && npm run build` (обязательная проверка таска 01 и финальная).
- Не трогать: `backend/`, `src-tauri/`, `node_modules/`, `features/dev/`, системные промпты `features/agent/prompts/**`, `engine/tools.ts` (описания инструментов), `@canvas-harness` внутри `node_modules`.

## Правила проекта (не обсуждаются в тасках)

- Меняются **только строковые литералы** на вызовы `t('…')`. Разметка, пропсы, логика, импорты, порядок элементов — не трогаются (G01).
- `en.json` — значения **вербатим** из кода: пунктуация, регистр, пробелы, переносы строк (G03). При `lng: 'en'` интерфейс обязан быть идентичен оригиналу.
- Ключи — по контексту: `<область>.<компонент>.<смысл>`, сегменты `snake_case`, например `agent.thinking`, `board.delete_confirm`, `settings.language_label` (G02).
- Одна и та же английская строка с разным смыслом — два разных ключа (G04).
- Технические строки не извлекаются: URL, имена событий, ключи `localStorage`, CSS-классы, идентификаторы, ключи Record (G05, R14).
- Системные промпты и tool descriptions не переводятся и не редактируются (R15, R32, G23).
- Sentence case в кнопках, меню и заголовках (G28).
- **Промежуточные коммиты (T02–T06):** каждый новый ключ добавляется и в `en.json` (вербатим), и в `ru.json` (временно тем же английским значением). Перевод появится в T07. Без этого `npm run i18n:check` краснеет на каждом шаге. В `ru.json` не оставлять пустых значений.
- Стиль webui: без `;`, именованные экспорты, без `any`, 2 пустые строки между top-level декларациями (R33).

## Модуль 1 — `webui/src/i18n/index.ts`

**Владеет:** экземпляром i18next, ресурсами, детектом языка, сохранением выбора.
**Экспортирует:**
- `initI18n(): Promise<void>` — идемпотентная инициализация; вызывается до первого рендера.
- `i18n` — экземпляр для `I18nextProvider` / тестов.
- `setLanguage(lng: 'en' | 'ru'): Promise<void>` — смена языка + запись `dim0.lang` + `document.documentElement.lang`.
- `getLanguage(): 'en' | 'ru'` — текущий язык.
- `SUPPORTED_LANGS`, `LANG_STORAGE_KEY = 'dim0.lang'`.
**Скрывает:** конфигурацию детектора, порядок `localStorage → navigator`, `fallbackLng`, формат ресурсов.
**Поведение:** `fallbackLng: 'en'`, `supportedLngs: ['en','ru']`, `load: 'languageOnly'`, `returnEmptyString: false`, `interpolation.escapeValue: false`. В тестах при `I18N_FORCE_LANG=en` детектор отключается, язык фиксирован. Ресурсы — статический импорт JSON (офлайн и single-file mini-app, без HTTP-backend).

## Модуль 2 — `webui/src/locales/{en,ru}.json`

**Владеет:** всеми ключами. Плоская структура с вложенностью по областям; один namespace `translation`.
**Экспортирует:** только данные. **Скрывает:** ничего.
**Инвариант:** набор ключей `ru` ⊇ набора `en`; пустых значений нет; для счётчиков — CLDR-формы (`ru`: `_one/_few/_many/_other`, `en`: `_one/_other`).

## Модуль 3 — `webui/src/components/language-toggle.tsx`

**Владеет:** UI-переключателем EN/RU. **Экспортирует:** `LanguageToggle` (named export), props — совместимые с `Button` (`React.ComponentProps<typeof Button>`).
**Скрывает:** способ сохранения и детект. **Поведение:** компактный dropdown в стиле `ModeToggle`, пункты «English» / «Русский», текущий отмечен; встраивается в футер сайдбара рядом с `ModeToggle`; новых панелей нет (R11, G10, G12).

## Модуль 4 — `webui/src/lib/i18n/errors.ts`

**Владеет:** переводом сетевых/серверных ошибок в текст на текущем языке.
**Экспортирует:**
- `localizeApiError(error: unknown, fallbackKey: string): string` — по HTTP-статусу и известному endpoint возвращает локализованный текст; иначе — исходный английский `detail`/`message` без изменений.
- `apiErrorKey(status: number, endpoint?: string): string | undefined` — чистый маппинг, тестируемый без сети.
**Скрывает:** таблицу статусов→ключей.
**Инвариант:** бэкенд не меняется; неизвестная ошибка никогда не превращается в общий текст — показывается как есть (G08, R34).

## Модуль 5 — `webui/scripts/i18n-check.mjs`

**Владеет:** проверкой паритета ключей. **Экспортирует:** CLI; `--strict`.
**Поведение:** отсутствующий в `ru` ключ → список + exit 1; пустое значение в `ru` → exit 1; лишний ключ в `ru` → предупреждение, exit 0 (при `--strict` → exit 1). Без внешних зависимостей (G18, G19).

## Тестовые швы

- `webui/src/test/setup.ts` — форсит `dim0.lang=en` и `I18N_FORCE_LANG=en` до импорта приложения (G14).
- `webui/playwright.config.ts` + `webui/e2e/setup.ts` — `storageState` с `dim0.lang=en` для origin `http://localhost:4321` (G13).
- `webui/e2e/i18n-ru.spec.ts` — единственный смоук на русский: ru → 2–3 русских текста → переключение на en (G15). Существующие 26 селекторов не переписываются (G16).

## Что каждый таск обязан соблюсти

1. Прочитать `notes.md` и этот файл.
2. Не выходить за свою директорию, кроме общего `en.json` (ключи добавляются блоками, отсортированными по области).
3. После правки: `npm run i18n:check` (если существует) и `npm run check-all`.
4. Никаких изменений в `backend/`, `src-tauri/`, `node_modules/`, `features/dev/`.
