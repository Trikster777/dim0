# Спецификация: русская локализация форка dim0 (i18n)

## Задача

Я веду личный форк dim0 — «думающего холста» с ИИ-агентом. Интерфейс полностью английский: я читаю подписи, ошибки и меню на неродном языке, а перевести их штатно нельзя — i18n в проекте нет, все строки захардкожены в `.tsx`. Мне нужен русский интерфейс, который не разваливается при каждом обновлении из upstream.

## Решение

В `webui/` появляется i18next с двумя локалями (`en`, `ru`) и переключателем EN/RU рядом с переключателем темы. Все пользовательские строки фронтенда заменяются на `t('…')` — только литералы, без перестройки разметки. Английская локаль вербатим, поэтому при `en` приложение выглядит как оригинал. Русская локаль покрывает весь `en.json`, склонения — через CLDR-формы. Бэкенд, системные промпты, `@canvas-harness` и десктопная оболочка остаются английскими и перечислены в `I18N.md`. Изменения ложатся серией коммитов по назначению, чтобы Sync fork давал конфликты только в строках.

## Решения по реализации

- **Библиотека:** `i18next` + `react-i18next` + `i18next-browser-languagedetector`. Ресурсы — статический импорт JSON, без HTTP-плагина: приложение офлайн-first, mini-app собирается в один файл. *Почему:* меньше точек отказа и зависимостей.
- **Один namespace `translation`** с точечными ключами. *Почему:* при Sync fork ключи из upstream кладутся в один файл рядом, без регистрации namespace.
- **Плоские JSON с вложенностью по областям**, ключи `<область>.<компонент>.<смысл>`. *Почему:* видно, куда положить новый ключ из upstream (G02).
- **Порядок детекта:** `localStorage['dim0.lang']` → `navigator.language` → `en`. `load: 'languageOnly'`, `fallbackLng: 'en'`. *Почему:* выбор пользователя важнее языка системы.
- **Смена языка** — `setLanguage()`: `i18n.changeLanguage`, запись `dim0.lang`, обновление `document.documentElement.lang`. *Почему:* одна точка правды.
- **Интерполяция:** `${…}` → `{{…}}`; плюрализация — ключи с `_one/_few/_many/_other` (ru) и `_one/_other` (en). *Почему:* русский требует четырёх CLDR-форм, включая `_other` для дробных.
- **Данные-массивы** (`THEMES`, `MODES`, `SLASH_COMMANDS`, `SEARCH_ENGINES`, `ToolNameDescription`, погодные коды): в данных остаётся ключ, `t()` вызывается при рендере. *Почему:* `t()` недоступен в момент создания констант, а перенос данных в рендер был бы рефакторингом (R31).
- **Ошибки:** `localizeApiError` по HTTP-статусу и endpoint; неизвестное — дословно. *Почему:* бэкенд не трогаем, но типовые сбои должны быть понятны.
- **Intl:** локаль = текущий язык (`ru-RU` / `en-US`) в 23 существующих местах; строка даты, уходящая в промпт (`agent/local/use-local-submit-prompt.ts:318`), не меняется. *Почему:* не менять вход LLM.
- **Обе точки входа** инициализируют i18n до рендера. *Почему:* иначе мигание языка и рассинхрон mini-app.
- **Сборка:** локальный `.env` копируется из `.env.sample`; `.env` не коммитится. *Почему:* `dotenv-cli` падает без файла.
- **Тесты:** `I18N_FORCE_LANG=en` отключает детектор в vitest; Playwright — `storageState` и setup-файл. *Почему:* результат не зависит от машины.
- **Коммиты:** `chore` (инфраструктура + переключатель) → `refactor` по областям (agent, board, sidebar, settings/signin, newsfeed/sharing/install, shared/ui) + `en.json` → `feat` (`ru.json`) → `docs` (`I18N.md`). *Почему:* так требует бриф и так проще разрешать конфликты.

## Открытые места

- **API `@canvas-harness` для подписей.** Пока `node_modules` не установлен, неизвестно, принимает ли библиотека `labels`/`locale`/конфиг меню. После `npm install` исполнитель T02 проверяет типы; если пропсы есть — использует (G30), если нет — оставляет как есть и фиксирует в `I18N.md`.
- **Точное число строк.** Нижняя оценка ~1013, реалистично 1100–1200. Итог фиксируется в отчёте по факту.
- **Подтверждение «dev-экран не в prod».** Маршрут регистрируется под `import.meta.env.DEV`; после сборки исполнитель проверяет отсутствие `capture-spike` в `dist/` и фиксирует в отчёте (G31).
